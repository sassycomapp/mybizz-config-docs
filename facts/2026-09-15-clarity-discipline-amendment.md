# Fact — clarity-discipline amendment (config-setup-prompt.md)

`C:\data-mybizz-mgt\prompts\config-setup-prompt.md` carries the
**clarity-discipline amendment (2026-09-15, appended append-only, developer
instruction, session 003–005)**. Its rules, as standing behavior for every
suite build executed from that prompt:

- The prompt is the task definition — scope is never re-confirmed, re-derived,
  or re-asked; if scope seems unclear, re-read the prompt, the register row,
  and the developer's instruction first.
- Procedural conflicts (e.g. a register row in `Deferred` where `WIP` is
  required) are resolved as an explicit named step in the plan — dated, with
  the developer's instruction cited — never as a question. The developer's
  instruction to run the prompt IS the authority for the documented state
  change.
- Questions are mandatory where they are genuine (a guard denial, a missing
  credential, a per-item gate decision, or a discovered subject-matter issue
  needing the developer's clarity) and forbidden where they manufacture
  confusion (re-treading settled ground, re-defining the task, introducing
  doubt where none exists).
- Open issues are never left open: every discovered issue carries to closure
  — a carried-forward watch row, a governance flag, or a gate item with the
  developer's disposition recorded. A run ends only with no workaround, no
  unresolved open issue, and no element in disrepair.
