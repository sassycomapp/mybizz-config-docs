# Durable fact — Developer standard on guard denials (2026-09-14)

An honoured guard denial never substitutes for a formal execution. When a
check is denied by a guard during an exam, audit, or verification run, the
run must re-execute that check as a clean, single-purpose command —
requesting a grant in the format `mg-grant --path <folder> --count N`
(handed to the developer to arrange) where a write or access permission is
required — or reclassify the check developer-run, handing the exact
command to the developer for verbatim recording. A denied check is never
marked as passed on evidence from an earlier session or an earlier point
in the same session; prior evidence may inform judgment but never
substitutes for a same-run execution.
