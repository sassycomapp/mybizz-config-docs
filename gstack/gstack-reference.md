## What GStack is (one line)

The workflow layer: slash-command skills for planning, building, reviewing,
and shipping software — GBrain is memory (stores and searches), GStack is
workflow (plans, builds, ships).

## Authority model

1. User decision in the current session
2. Authoritative repo files and ADRs
3. OpenCode rules (global + project AGENTS.md, opencode.json)
4. GStack workflow conventions
5. GBrain advisory memory

When GStack workflow expectations conflict with OpenCode config, project
rules, or user instruction — the stricter layer wins.

## Workflows

Three core workflow families, named against whichever project is currently
active (see [[[mybizz-config-docs:opencode/opencode-reference|Commands, Verification, Troubleshooting]]](C:/mybizz/mybizz-config-docs/opencode/opencode-reference.md), Active Project Standard).

### docs-plan (active project's `-project-library` repo)

**Use when:** analysis, validation, architecture, planning, ADR work, prompt authoring.
**Agent:** plan (primary)
**Skills:** `/office-hours`, `/plan-ceo-review`, `/plan-eng-review`, `/plan-design-review`

**Mandatory initial steps:**
1. Consult [[[pdlf:pdlf-library/docs-local/dev-makepdlf-todo|Active PDLF To-Do List]]](C:/pdlf/pdlf-library/docs-local/dev-makepdlf-todo.md) — incorporate relevant items, mark completed as `[DONE]`
2. Consult ADR folder — treat as authoritative, create new ADRs for new decisions

**Exit condition:** planning objective complete, OR build-ready handoff prepared, OR canonical tracking updated.

### code-plan-build (code repos)

**Use when:** implementation, refactoring, migration, code validation, file edits.
**Agent:** build (primary), plan for complex/risky work
**Skills:** `/investigate`, `/review`, `/qa`, `/ship`

**Mandatory initial steps:**
1. Confirm repo path
2. Consult [[[pdlf:pdlf-library/docs-local/dev-makepdlf-todo|Active PDLF To-Do List]]](C:/pdlf/pdlf-library/docs-local/dev-makepdlf-todo.md) for relevant items
3. Consult ADRs for architectural baseline

**Mandatory checks before edits:** repo path confirmed, protected files checked, backup rule applied, timestamp rule applied, write scope checked.

**Exit condition:** implementation complete, validation recorded, tracking requirements handed off.

### status-handover (cross-workspace)

**Use when:** session close, checkpoint, handover for continuation.
**Agent:** plan (primary)
**Skills:** `/context-save`, `/context-restore`

**Exit condition:** current state captured clearly enough for a fresh session to resume without reconstructing context.

## Handoff contract

Work that changes ownership (Plan↔Build, docs↔code, session↔session) must
produce a structured handoff.

### Plan→Build template

```
Task summary:
Scope in:
Scope out:
Files read:
Relevant ADRs:
Files expected to change:
Files that must not change:
Key constraints:
Implementation steps:
Validation required:
Tracking handoff required (devlog / todo / ADR):
```

### Build→Plan template

```
Completion status:
Files changed:
Backup confirmation:
Protected-file confirmation:
Validation result:
Implementation summary:
Proposed devlog handoff:
Proposed todo handoff:
Proposed ADR updates:
```

### Quality bar

A handoff is acceptable only if: short and specific, file paths explicit,
scope boundaries clear, ADRs and tracking expectations visible, unresolved
risks listed, sufficient for a new session to continue without reconstructing
context.

## Artifact locations

**FACT (recorded 2026-09-16, verified live).** Every GStack skill saves its
output to a per-project directory on disk, and downstream skills locate prior
output through that same directory.

**Where skills save:**

- **Internal save (primary, per project, LIVE):** `~/.gstack/projects/$SLUG/`
  where `$SLUG` is the deterministic per-repo project slug produced by
  `gstack-slug` (e.g. `sassycomapp-mybizz-config-docs` for this repo). Every
  skill writes here first — that is the single machine-wide home for GStack
  artifacts. Verified live 2026-09-16 across the populated project trees.
- **Repo-visible copy (convention, NOT realized):** per AGENTS.md, the
  artifact should also be copied to `gstack-outputs/` in the active project
  repo. **This convention is not live on this system** — verified 2026-09-16:
  no `gstack-outputs/` folder exists in any project root (the only match
  anywhere is inside a backup folder, which is out of scope). Treat
  `~/.gstack/projects/$SLUG/` as the sole authoritative artifact location;
  do not rely on a repo-side copy existing.

**Sub-directory layout inside `~/.gstack/projects/$SLUG/` (per skill; LIVE):**

| Skill | Internal save | Repo copy (convention) |
|---|---|---|
| `/office-hours` | `~/.gstack/projects/$SLUG/` | `gstack-outputs/` |
| `/plan-ceo-review` | `~/.gstack/projects/$SLUG/ceo-plans/` | `gstack-outputs/` |
| `/plan-eng-review` | `~/.gstack/projects/$SLUG/` | `gstack-outputs/` |
| `/plan-design-review`, `/plan-devex-review` | `~/.gstack/projects/$SLUG/` | `gstack-outputs/` |
| `/design-consultation` | `~/.gstack/projects/$SLUG/designs/` | `gstack-outputs/` + [[[mb-3-cs-project-library:docs-local/design\|DESIGN]]](C:/dev/dev-mb-3-cs/mb-3-cs-project-library/docs-local/DESIGN.md) → `docs/` |
| `/retro` | `~/.gstack/projects/$SLUG/retros/` | `gstack-outputs/` |
| `/context-save` | `~/.gstack/projects/$SLUG/.context/` | — |
| `/qa`, `/qa-only` | `~/.gstack/projects/$SLUG/qa-reports/` (observed live) | `gstack-outputs/` |
| `/health` | `~/.gstack/projects/$SLUG/health/` (observed live) | — |
| `/cso` | `~/.gstack/projects/$SLUG/security-audits/` (observed live) | `gstack-outputs/` |
| `/spec` | `~/.gstack/projects/$SLUG/specs/` (observed live) | — |

(Sub-directories observed live in the populated project trees under
`~/.gstack/projects/`. Where a skill is not listed, assume the bare
`~/.gstack/projects/$SLUG/` root. The "Repo copy" column records the AGENTS.md
convention only — none of those copy locations currently exist on this system.)

**How subsequent skills find prior output:**

1. Compute the same slug: `eval "$($GSTACK_BIN/gstack-slug)"` →
   `$SLUG` (deterministic per repo — a later skill in the same project
   resolves to the same directory).
2. Read the skill's known sub-directory (table above) for the prior run's
   artifact.
3. Cross-session handoff: `/context-save` writes `.context/`; `/context-restore`
   reads it — the standing handoff pair for a fresh session to resume without
   reconstructing context.
4. Learnings compound across sessions via
   `~/.gstack/projects/$SLUG/learnings.jsonl` (loaded at every skill preamble
   once it exists).
5. Timelines (`timeline.jsonl`), analytics (`~/.gstack/analytics/`) and
   decisions (`decisions.active.json`) are also project-keyed at
   `~/.gstack/projects/$SLUG/` and readable by later skills. These files
   appear on first use (verified: absent until the first event writes them).
6. The `gstack-outputs/` copy lane does **not** exist on this system (verified
   2026-09-16) — it is an un-realized AGENTS.md convention. Never rely on it as
   a fallback; find prior output only under `~/.gstack/projects/$SLUG/`.

Deterministic slug example (this repo, verified live 2026-09-16): `gstack-slug`
→ `sassycomapp-mybizz-config-docs`.

## OpenCode integration

GStack is exposed via skills (slash commands), not a separate CLI. No
`.opencode/gstack` config exists — deliberate, to keep authority with
OpenCode. Command naming follows frontmatter `name:` fields — full rules in
[[[mybizz-config-docs:gstack/gstack-skills-reference|GStack Skills Reference]]](C:/mybizz/mybizz-config-docs/gstack/gstack-skills-reference.md).

  `bun run gen:skill-docs`.

  not leftover.
- Do not assume the folder name is the command (see skills-reference).
- Do not run `/sync-gbrain --dream` against a manually-registered source.
- Do not trust `/setup-gbrain`'s own GBrain backend description.
- Do not remove the OpenClaw skill folders — updates recreate them; removing
  is churn, not a fix.
