# Work Package 10A — Investigate Graphify MCP Tool Exposure

Read-only investigation into why Graphify MCP tools are not exposed to the
OpenCode agent even though the server answers a direct stdio handshake. No
files modified, no config change, no install, no commit/push, no sync-gbrain.

---

## Confirmed root cause

The OpenCode **process instance** bootstrapped **before** `mcp.graphify` was
added to the project config, and a new chat session does not re-spawn MCP
servers.

Timeline (UTC log times → SAST `+0200`):

| Time (+0200) | Event |
|---|---|
| 13:33:03–05 | Process bootstrap — config loading (incl. `mb-3-cs/opencode.json`). `mcp.graphify` did not exist yet. |
| 13:33:08–10 | MCP discovery: only `service=mcp key=gbrain type=local found` → `toolCount=110`. No `key=graphify` anywhere. |
| 13:34:14 | Chat session #1 (`sunny-circuit`) created. |
| 14:46:17 | Package 9 adds `mcp.graphify` to `opencode.json` (file mtime). |
| ~14:56 | Package 9.1 installs `graphifyy[mcp]`. |
| 15:04:34 | Chat session #2 (`happy-squid`) created — the WP10 "fresh session", but not a process restart. |

Key log evidence (from `~/.local/share/opencode/log/2026-08-14T113303.log`):

- `service=default directory=/mnt/c/dev/dev-mb-3-cs/mb-3-cs creating instance`
  and `bootstrapping` occur **once** (13:33). No second occurrence later.
- `service=mcp key=gbrain … toolCount=110 create() successfully created client`
  is the only MCP spawn; no `key=graphify` line exists anywhere in the log.
- The only MCP `ERROR` is `clientName=gbrain … -32601 Method not found`
  (harmless `get prompts`), unrelated.

The WP10 "fresh session" was a new **chat** session inside the already-running
instance. MCP servers are spawned once per **process** at bootstrap, which
happened before the config change — so `graphify` was never started.

**Certainty:** timing facts are clearly defined (log + file mtimes). The
mechanism (MCP spawned only at bootstrap; new chat ≠ restart) is a
high-confidence inference from the log structure, not from reading OpenCode
source.

   13:33 +0200, before `mcp.graphify` was written (14:46 +0200); MCP servers
   are only spawned at bootstrap, so graphify was never launched.
2. **Whether a fresh session is sufficient** — A new chat session is **not**
   sufficient (proven: `happy-squid` at 15:04 did not re-spawn MCP). A **full
   process restart** is sufficient.

4. **Command required** — None. No config or install command is needed; only
   a process restart.
5. **Configuration changes needed** — **No.** The `mcp.graphify` entry is
