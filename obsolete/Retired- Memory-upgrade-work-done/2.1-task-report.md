## Anomalies / findings

1. **`extract` does not produce `GRAPH_REPORT.md` or `graph.html` in 0.9.40.**
   The tool's own output directs a follow-up `graphify cluster-only` to generate
   both. Not run (scope restricted to the initial extraction). Version-dependent
   behavior — flagged, not an error.
2. **Anvil `.html` form templates are under-represented.** 95 nodes carry
   `source_file: ""` — these are template *class references* (e.g.
   `BlogEditorFormTemplate`, `BookingCalendarFormTemplate`) extracted from form
   `__init__.py`, while the actual `.html` templates were classified as
   "documents" and skipped by `--code-only`. The UI-template layer is present
   only as ghost nodes without extracted content.
3. **`--no-gitignore` pulled in tooling files, not just `tests/`.**
   `opencode.json` (root, 1,033 B) produced 33 nodes (permission patterns such as
   `*DROP DATABASE*`, `git clean -fd*`), and `.opencode/` produced 10 —
   tooling config noise, not application source.
4. **`node_modules` was still excluded.** Despite `--no-gitignore`,
   `.opencode/node_modules` (3,445 files) produced 0 nodes — graphify's detector
   hard-excludes it. The pre-run concern about node_modules bloat did not
   materialize; note `--no-gitignore` is narrower than "include everything".
5. **Minor accounting discrepancy:** graphify reported "4 file(s) not
   classified" but listed only 3 (`.gitignore`, `pytest.ini`, `theme.css`).
6. **Graph is undirected** (`directed: False`). Relevant to the unresolved
   directed-vs-undirected question from Package 2 (plan).
