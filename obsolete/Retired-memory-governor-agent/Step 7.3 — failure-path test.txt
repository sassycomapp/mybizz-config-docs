Now the actual defect this whole detour surfaced. register_candidate() unconditionally writes date-state-changed: now() every time it's called, on the existing row, even when nothing about the candidate has actually changed since the last attempt. That's why every retry produced a genuinely different file, and git status --porcelain correctly (and unhelpfully) saw a real change worth committing each time.
