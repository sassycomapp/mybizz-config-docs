Step 5.3 — Contract testing with Schemathesis

Two things to flag before running anything, same discipline as every step.

1. Every endpoint requires the X-Governor-Credential header, and Schemathesis doesn't know that's a real secret. Without telling it a valid value, it will overwhelmingly generate requests that correctly get rejected with 401 — testing our auth boundary, but nothing past it. I'll pass the real Step 0.3 credential as a fixed header on every generated request, so the fuzzer actually exercises real business logic, not just the front door.

2. A genuine, likely finding I want to name before running rather than after: none of the eleven endpoints in api.py declare explicit responses={...} metadata — every HTTPException (401, 404, 400, 409) is a real runtime behavior, but it was never declared in the OpenAPI schema itself. Schemathesis's status_code_conformance check specifically looks for exactly this mismatch — a response code the app returns that the spec never said it could return. I expect this to fail initially, not because the app is broken, but because the documentation of its own error responses is incomplete. Worth distinguishing that from a real defect once we see actual results, not before.

A second, more concerning possibility I want flagged going in: submit_candidate() never checks whether owning_project actually exists before attempting the insert — unlike every other endpoint, which calls get_candidate/get_project first. If that's true, a fuzzed owning_project value hitting the memory_candidates.owning_project foreign key would raise psycopg.errors.ForeignKeyViolation uncaught, producing a real HTTP 500 — exactly what Schemathesis's not_a_server_error check exists to catch. I'm not fixing this preemptively; letting the tool actually surface it live, since that's the whole point of this step.
