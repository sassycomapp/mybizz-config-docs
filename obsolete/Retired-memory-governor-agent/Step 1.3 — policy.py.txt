Step 1.3 — policy.py

Before the code — one real spec inconsistency surfaced while implementing this, worth flagging clearly rather than quietly resolving, since guessing wrong here is exactly the kind of "policy hole" this whole project exists to prevent.

Architecture §2 names five HIGH_RISK_TYPES: policy, credential, identity, architecture, security. Only policy is actually a valid MemoryType value. Checking models.py directly: MemoryType = Literal["fact", "preference", "policy", "episode", "trace", "task_state", "relationship", "summary", "procedural"] — credential, identity, architecture, and security don't exist as memory types anywhere in this codebase. This almost certainly carried over unedited from the v1 sketch's risk taxonomy and was never reconciled when models.py's MemoryType enum was finalized. I'm not silently picking an interpretation and moving on — implementing HIGH_RISK_TYPES = frozenset({"policy"}) as the only defensible literal reading, with the inconsistency documented directly in the code and flagged here. If those four concepts are meant to be governed as high-risk, the real fix belongs in models.py's enum (or a separate content-classification field) — that's a decision for you, not something I should invent.

Two smaller, related design points, same discipline as Step 1.2:

Cross-project sharing risk elevation (Architecture §2: "scope changes that add or remove a shared_with project are treated as high risk") describes an event — a diff against a prior state — which requires storage that doesn't exist until Phase 2. At this phase, I'm using the closest static approximation available: any candidate not scoped project_local is treated as elevated (medium) risk. Not identical to the spec's intent, but the honest interim substitute.
check_scope's v1 analog checked restricted visibility — a value that no longer exists (removed as multi-tenant scaffolding, Scope Doc §5). I've replaced it with a consistency check grounded directly in Scope Doc §6's own definitions: project_local requires empty shared_with, shared_all requires exactly ["all"], shared_specific requires a real non-empty explicit list.

One more, load-bearing: decide_path() returns a Policy object and mutates nothing. It does not touch candidate.status, and this module does not import state_machine.py at all — preserving both Architecture §9's dependency ordering and Step 1.2's enforcement test (only state_machine.py may assign .status). Wiring decide_path()'s output into an actual apply_decision() call is Phase 5's job (api.py), not this module's.
