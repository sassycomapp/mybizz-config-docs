Step 0.3 — Provision per-writer API credentials

Per Architecture §3.3, the Memory Governor needs one distinct credential per known writer — at minimum GBrain-dreaming and manual developer submission — so writer_identity can be derived server-side from which credential authenticated a request, never trusted from the payload (Scope Doc §11). Exit criteria (Workflow Step 0.3): two distinct credential values exist and are recorded somewhere retrievable, not hardcoded into anything that will be committed.

At this stage, the governor's API doesn't exist yet (Phase 5), so there's no real auth system to issue these against — we're just generating and storing the values now, correctly, so Phase 3 (provenance.py) and Phase 5 (api.py) have something real to wire up later rather than inventing placeholder secrets then.

---
dev-p@dev-p:~$ cd /home/dev-p/memory-governor

# Generate two distinct, strong random credentials
MG_CRED_GBRAIN_DREAMING=$(openssl rand -hex 32)
MG_CRED_MANUAL_SUBMISSION=$(openssl rand -hex 32)

# Append to .env — already gitignored, confirmed in Step 0.1
cat >> .env <<EOF

# Per-writer API credentials (Architecture §3.3) — one per known writer.
# writer_identity is resolved server-side from which of these authenticated
# the request; never accept writer_identity from a request payload.
MEMORY_GOVERNOR_WRITER_GBRAIN_DREAMING=${MG_CRED_GBRAIN_DREAMING}
MEMORY_GOVERNOR_WRITER_MANUAL_SUBMISSION=${MG_CRED_MANUAL_SUBMISSION}
EOF
chmod 600 .env

# Confirm .env is still git-ignored after the append (re-verify, don't assume)
git check-ignore -v .env

# Confirm both values are present and genuinely distinct (lengths only, never the values themselves)
grep -c "MEMORY_GOVERNOR_WRITER_" .env
echo "gbrain-dreaming credential length: ${#MG_CRED_GBRAIN_DREAMING}"

  echo "DISTINCT_CREDENTIALS: true"

fi
