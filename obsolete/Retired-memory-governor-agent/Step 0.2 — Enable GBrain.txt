Step 0.2 — Enable GBrain MEMORY_VERBS

Per gbrain-reference.md, this surface was added in 0.43.0.0, opt-in via gbrain config set mcp_surface verbs, and confirmed not yet enabled in this environment. Exit criteria (Workflow Step 0.2) requires the five tools — remember/recall/entity/synthesize/forget — confirmed reachable, not just the config flag set. Setting the flag alone doesn't prove the MCP server actually serves them, so this block does both.

One thing worth flagging before you run it: this test starts gbrain serve directly as a standalone process to do a raw MCP handshake — independent of OpenCode entirely. That's deliberate and matches how the Graphify MCP server was verified in the earlier project (a direct stdio handshake, not through a live OpenCode session) — it means this verification isn't affected by the MCP bootstrap-timing behavior documented in gbrain-reference.md (servers only spawn at OpenCode process startup). If you later open an OpenCode session and the gbrain_remember/gbrain_recall etc. tools don't appear there, that's the already-known restart issue, not a sign this step failed — worth remembering when Phase 12 comes around.

import subprocess, json, sys

proc = subprocess.Popen(
    ["/home/dev-p/.bun/bin/gbrain", "serve"],
    stdin=subprocess.PIPE, stdout=subprocess.PIPE, stderr=subprocess.PIPE,
    text=True, bufsize=1
)

def send(msg):
    proc.stdin.write(json.dumps(msg) + "\n")
    proc.stdin.flush()

def recv():
    line = proc.stdout.readline()
    return json.loads(line) if line else None

send({"jsonrpc": "2.0", "id": 1, "method": "initialize",
      "params": {"protocolVersion": "2024-11-05", "capabilities": {},
                 "clientInfo": {"name": "step-0.2-verify", "version": "0.1"}}})
init_resp = recv()

send({"jsonrpc": "2.0", "method": "notifications/initialized"})

send({"jsonrpc": "2.0", "id": 2, "method": "tools/list"})
tools_resp = recv()

proc.terminate()
try:
    proc.wait(timeout=5)
except subprocess.TimeoutExpired:
    proc.kill()

if not tools_resp or "result" not in tools_resp:
    print("HANDSHAKE_FAILED")
    print("init:", init_resp)
    print("tools:", tools_resp)
    stderr_output = proc.stderr.read()
    print("stderr:", stderr_output[:2000])
    sys.exit(1)

tool_names = sorted(t["name"] for t in tools_resp["result"]["tools"])
print(f"TOTAL_TOOLS: {len(tool_names)}")
expected = {"remember", "recall", "entity", "synthesize", "forget"}
found = {name for name in tool_names if any(v in name for v in expected)}
print(f"MEMORY_VERBS_MATCHED: {sorted(found)}")
missing = expected - {v for name in tool_names for v in expected if v in name}
if missing:
    print(f"MISSING: {sorted(missing)}")
    sys.exit(1)
else:
    print("ALL_FIVE_VERBS_PRESENT: true")
PYEOF

Yes, this is correct — and it's worth walking through why, since two lines in there look like they could be problems but genuinely aren't.

Version 0.46.1.0, comfortably above the 0.43.0.0 floor. Fine.

The "config" already read verbs before you set it. Look closely: gbrain config get mcp_surface on the baseline check (before set) already printed verbs, not something else. This means MEMORY_VERBS was actually already enabled somewhere between when gbrain-config.md was written and now — a real, useful correction to the record, not a mistake in your run. The set command re-affirmed the same value; harmless, and now we have current, verified truth instead of a stale document claim. gbrain-config.md needs a small factual update for this later.

The self-upgrade nag (0.46.1.0 -> 0.46.12.3 available) is just noise, ignore it. Per Scope Doc §16 and the standing policy in gbrain-config.md, upgrades happen only on an actual check failure — none failed here, so this is correctly left alone, not something to act on.

[config] source: db plane is informational, telling you the setting is read from GBrain's database-backed config rather than a flat file — expected, not a warning.

The handshake result is the one that actually matters, and it's a clean pass: 114 total tools exposed, and critically the pattern-match found entity, forget, recall, remember, synthesize — all five required verbs, each present as their own real tool name (not just a substring collision — forget_fact and get_brain_identity showing up alongside them is just the matcher being loose on purpose, harmless overmatch, not a problem). Script's own logic confirms it: ALL_FIVE_VERBS_PRESENT: true only prints if none of the five expected verbs were missing.
