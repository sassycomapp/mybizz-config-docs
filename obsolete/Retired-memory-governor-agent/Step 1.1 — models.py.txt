Real, clear bug — not a transient issue. setuptools's automatic package discovery found two top-level directories (app/ and registers/) and correctly refused to guess which one is the actual Python package, since registers/ is data (the git-tracked backup store from Architecture §8), not code. pyproject.toml from Step 0.4 never told it explicitly. This would have surfaced eventually regardless of when we hit it — better now, before any real content exists.

(The pip self-upgrade had a one-off DNS hiccup — Temporary failure in name resolution — but it retried and succeeded on its own; that's ordinary WSL network flakiness, not something to chase unless it recurs.)

Fix: tell setuptools explicitly that app is the package, nothing else.
