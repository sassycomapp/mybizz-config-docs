## 4. Exact destination options (CLI capability)

`scaffold` syntax unchanged: `<name> | <source> | --all [--workspace PATH]
[--dry-run] [--trust] [--no-cache] [--json]`.

- **Destination selection:** `--workspace PATH` ✓ (writes `<PATH>/skills/…`)
- **OpenCode-specific output flag:** none (host-agnostic)
- **Dry-run:** `--dry-run` ✓
- **JSON:** `--json` ✓
- **Selective selection:** `scaffold <name>` (single) or `--all` ✓
- **Overwrite protection:** additive, refuses to overwrite ✓

Because scaffold writes `<workspace>/skills/`, targeting
`--workspace …/mb-3-cs/.opencode` yields exactly `…/.opencode/skills/<slug>/SKILL.md`
— the project-local OpenCode skill directory.

## 5. Compatibility findings

- Skills are **host-agnostic** `SKILL.md` files with `name` + `description` +
  optional `triggers`/`version`/`upstream`/`tools` — the `name`+`description` pair
  is exactly what OpenCode needs; extra fields are ignored.
- Host mentions are **documentation, not blockers**: `OpenClaw` appears in 11
  files, `Hermes` in 2, `Claude Code` in 3 — all as "works with / platform-agnostic"
  prose (e.g. `ask-user` states "Platform-agnostic — works on Telegram, Discord,
  CLI, or any agent"). No host-specific dependency prevents OpenCode use.
- No adaptation of host-specific instructions is required.

## 6. Resolver / routing findings

- OpenCode routes by skill `name`+`description` through the `skill` tool, with
  **manual invocation** — it does **not** consume `triggers` or a resolver.
- `RESOLVER.md` is **not required** by these skills for OpenCode.
- The missing resolver is **not a functional defect** — it only removes optional
  auto-dispatch that OpenCode does not perform anyway.
- The old "referenced-but-missing" resolver skills are now **mostly bundled**
  (`ask-user`, `brain-taxonomist`, `capture`, `cold-start`, `eiirp`, `publish`);
  a few remain absent (`frontmatter-guard`, [[step-43-staging-smoke-test|Step 43 Staging Smoke Test]], `schema-author`,
  `schema-unify`, `gbrain-upgrade`, `migrate`, `setup`) — but this is moot since
  no resolver is scaffolded.

## 8. Recommended implementation option

**Option A — scaffold into project-local `.opencode/skills/`** (directly
achievable, local-only, auto-discovered, collision-free except `skillify`).

| Option | Verdict |
|---|---|
| A — `.opencode/skills/` | **Recommended** |
| B — global `~/.config/opencode/skills/` | Rejected — pollutes the shared global dir across all projects |
| C — temp + symlink | Rejected — symlink discovery is unverified; no benefit over A |
| D — reference-only | Rejected — no auto-discovery |
| E — instructions mapping | Optional complement to A, not standalone |

Rationale for A: `.opencode/` is gitignored (consistent with the WP11 local-only
decision); `.opencode/skills/` is currently absent so there is no collision risk;
OpenCode auto-discovers it; and it requires no symlink or global-dir pollution.
