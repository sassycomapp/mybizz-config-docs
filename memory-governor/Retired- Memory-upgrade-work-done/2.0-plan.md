## 3. Proposed Package 2 action

**Correct initial command:** `graphify extract <path> --code-only` (the headless
CLI command), **not** `/graphify <path>`.

Rationale:

- `/graphify <path>` is the OpenCode **skill** invocation, not a raw CLI
  command. It drives the full interactive pipeline (detect → AST + semantic
  subagent dispatch → build → cluster → label communities → HTML) and, for a
  doc-bearing corpus, can invoke LLM community naming (non-deterministic). For
  a code-only baseline it is overkill.
- `graphify extract <path>` is the "headless full extraction … for CI/scripts"
  — the deterministic one-shot equivalent.
- `--code-only` = "local AST, no API key" → deterministic and free.

**Exact command for mb-3-cs:**

```bash
graphify extract /mnt/c/dev/dev-mb-3-cs/mb-3-cs --code-only
```

- **Explicit output directory not required.** Default `--out` is `<path>`, so it
  writes to `/mnt/c/dev/dev-mb-3-cs/mb-3-cs/graphify-out/`. Passing
  `--out /mnt/c/dev/dev-mb-3-cs/mb-3-cs` is optional and equivalent.
- **Mode:** normal (omit `--mode deep`). Deep mode = "aggressive INFERRED-edge
  *semantic* extraction" — LLM work that only applies to docs/papers/images and
  is skipped by `--code-only` anyway.
- **No `--force`** (first run), **no `--backend`/`--model`** (irrelevant for
  code-only), **no `--global`** (would mutate `~/.graphify/global-graph.json`
  — out of scope).

## 4. Proposed Package 2 verification

Run after extraction, before any acceptance:

1. **Artifacts exist:** `graphify-out/graph.json`, `GRAPH_REPORT.md`,
   `graph.html` all present and non-empty.
2. **Graph non-empty:** `graph.json` node count > 0 (e.g.
   `python3 -c "import json;print(len(json.load(open('graphify-out/graph.json'))['nodes']))"`).
3. **Scope cleanliness:** `git status --short` and `git diff --stat` show only
   the new untracked `graphify-out/` directory — no project source files
   touched.
4. **Structural sanity:** `graphify god-nodes --graph …/graphify-out/graph.json`
   lists hubs.
5. **Query works:** `graphify query "<question>" --graph …/graphify-out/graph.json`
   returns a non-trivial answer.
6. **Integrity:** `graphify diagnose multigraph --graph …/graphify-out/graph.json`
   reports no collapsed/dangling edges.
7. **Determinism (optional but recommended before asserting it):** re-run the
   same `extract --code-only`, then diff/hash `graph.json` across the two runs —
   expect byte-identical.

## 5. Risks / unresolved ambiguities

1. **Exact CLI output set unverified.** `graphify extract` has no dedicated help
   page; its output files are inferred from SKILL.md Step 6 and the
   `cluster-only` description. Verification step 1 must confirm all three
   artifacts actually materialize (and note any extra sidecars like
   `.graphify_labels.json`, `cost.json`, `.graphify_python`).
2. **Corpus size unknown until `detect` runs.** SKILL.md warns at >500 files or
   >2M words and asks to narrow scope. mb-3-cs has ~254 code chunks (GBrain)
   plus many Anvil form `.py` files — likely under threshold, but the graph may
   still be large; graph.html has a >5,000-node warning. Observe at runtime.
3. **`tests/` exclusion.** The code repo's `.gitignore` lists `tests/`, and
   graphify honors `.gitignore` by default — so tests will be omitted unless
   `--no-gitignore` is passed. Decision needed: include tests or not.
4. **Directed vs undirected.** `graphify extract` help shows no `--directed`
   flag (that flag appears only in the SKILL's `/graphify --directed` usage).
   Default is undirected. If the Task 3.7 "dependency checking" goal needs
   source→target edge direction, the undirected baseline may be insufficient —
   unresolved.
5. **Dead cross-reference.** [[master-task-list|mybizz-OS]] does not exist in either
   repo, and "Task 3.7" is only matched by an unrelated DB-table heading. The
   AGENTS.md (and gitignored duplicate [[agents|mb-3-cs]]) reference to "Task 3.7 —
   Graphify dependency checking" is a stale/dead link; its intended scope is
   unknown and should not be assumed.
6. **`.gitignore` gap.** `graphify-out/` is not currently ignored in either
   repo, so after the run it appears as untracked. Adding it to `.gitignore` is
   a separate modification requiring approval (not part of the extraction
   itself).
7. **Determinism edge case.** AST extraction is deterministic, but
   community-detection ordering is asserted only by the "deterministic and
   fast" claim; verification step 7 (two-run hash) is the honest way to confirm
   before stating it as fact.
