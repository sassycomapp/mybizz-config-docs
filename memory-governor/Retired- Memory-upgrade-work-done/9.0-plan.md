## 3. Exact Graphify MCP configuration required

Graphify ships an MCP stdio server: `python3 -m graphify.serve <graph.json>`
(module `graphify/serve.py`). Tools (10): `query_graph`, `get_node`,
`get_neighbors`, `get_community`, `god_nodes`, `graph_stats`, `shortest_path`
(+ `list_prs`, `get_pr_impact`, `triage_prs`).

Proposed OpenCode config (mirrors the working `gbrain` entry):
```jsonc
"mcp": {
  "graphify": {
    "type": "local",
    "command": [
      "/usr/bin/python3",
      "-m", "graphify.serve",
      "/mnt/c/dev/dev-mb-3-cs/mb-3-cs/graphify-out/graph.json"
    ],
    "enabled": true
  }
}
```
(`/usr/bin/python3` verified: `import graphify, graphify.serve` succeeds. No
`environment` block needed.)

## 4. Uses existing graphify-out/graph.json?

**Yes** — serve command takes the graph.json path directly (`serve.py`
`_load_graph`; exports reference).

## 5. Manual vs auto-launch

**Auto-launched by OpenCode.** `type: "local"` MCP servers are spawned at
session start, like the working `gbrain` entry. No manual start. (Errors on
start if `graph.json` is absent.)

## 6. API key required (code-only graph)?

**No.** `serve.py` reads graph.json with `networkx`, serves read-only queries,
imports security helpers but no LLM/API-key code. The 7 core tools are key-free.
(The 3 PR-triage tools may expect a GitHub CLI/token — irrelevant here.)

## 7. Would it modify AGENTS.md or other files?

**No AGENTS.md change.** Adding `mcp.graphify` touches only an OpenCode config
file. (`graphify opencode install` would edit AGENTS.md + write a plugin — not
used here; the manual `mcp` entry is AGENTS.md-neutral.)

## 8. Graphify vs GBrain tool disambiguation

Clear and unambiguous:
- **GBrain**: `gbrain_*` (`gbrain_query`, `gbrain_get_page`, `gbrain_code_*`,
  `gbrain_recall`) — knowledge brain, PostgreSQL-backed, semantic + memory.
- **Graphify MCP**: `query_graph`, `get_node`, `get_neighbors`,
  `get_community`, `god_nodes`, `graph_stats`, `shortest_path` — code
  relationship graph, local `graph.json`.
No name overlap; distinct backends.

## 10. Conflict with .opencode/plugins/graphify.js?

**None.** Plugin = bash reminder hook; MCP = separate tool provider. Both point
at the same `graph.json`; they do not touch the same mechanism.

## Files that would change

Exactly one, depending on placement:
- **Recommended:** repo root `opencode.json` (project-scoped; already
  local-only since `opencode.json` is gitignored) — add the `mcp.graphify`
  block. Alternative: global `~/.config/opencode/opencode.jsonc` (bakes a
  repo-specific absolute path into every project).

No `.graphifyignore`, `.gitignore`, `AGENTS.md`, hooks, packages, or source
changes.

## Risks

1. **Absolute-path fragility** — hardcoded checkout path; breaks on repo move or
   graph deletion (fresh clone has no `graph.json` until rebuild).
2. **Redundancy** — graphify CLI (`path/query/god-nodes/explain`) already
   provides identical queries; MCP is convenience, not capability.
3. **3 irrelevant bundled tools** (`list_prs`/`get_pr_impact`/`triage_prs`) —
   harmless noise.
4. **Config-file change only** — gitignored/local, won't propagate to clones.

## Recommendation

Feasible and low-risk (no API key, no AGENTS.md/hooks/package/PostgreSQL
changes, no conflict). Optional — the CLI already covers the same queries, and
the config carries a repo-specific absolute path.

- **Approve only if** first-class in-session `graph_*` tools are wanted.
- **Defer** if the CLI workflow suffices.
- If approved, the next package is a single edit to repo `opencode.json` adding
  the `mcp.graphify` block above, then the two verification queries (§9).
