## 1. Correct `.graphifyignore` syntax (from detect.py L950–1205)

Full gitignore spec:

- Blank lines and `#` full-line comments ignored; inline `#` requires a
  preceding space; `\#` = literal `#`.
- `!` negation (un-ignore), last-match-wins.
- Trailing `/` = directory-only; `**` = recursive glob; `*` matches within one
  path segment (not across `/`).
- Anchored patterns (containing `/`) are root-anchored; bare names match at any
  depth.
- Parent-exclusion rule: `!` cannot re-include a file whose ancestor directory
  is already excluded.
- Merge order: `.gitignore` read first, `.graphifyignore` last →
  `.graphifyignore` wins (can only exclude more).
- **Critical**: `.graphifyignore` is honored even when `--no-gitignore` is set
  (with `gitignore=False` only `.graphifyignore` is read, not `.gitignore`). It
  is the correct lever regardless of the persisted config.

## 2. Can HTML be structurally extracted? — No

- `.html` ∈ `DOC_EXTENSIONS` (`detect.py` L34), not `CODE_EXTENSIONS` (L33).
  Same for `.yaml`/`.yml`.
- No plain-HTML AST extractor exists (`extractors/` has no `html.py`;
  `extract.py` only handles `.cshtml`/`.razor`/`.phtml`/`.svelte`/`.vue`/`.astro`
  — code-with-embedded-HTML, not plain HTML). `json_config.py` covers JSON only,
  not YAML.
- **Plain HTML (and YAML) = document → semantic (LLM) extraction only.** There
  is no deterministic, no-LLM path.

## 3. Does HTML require semantic/LLM? — Yes

Semantic extraction = LLM. Backends: `gemini|kimi|claude|openai|deepseek|ollama`.
With no key: `ValueError: No LLM backend configured` (`llm.py` L1753).

## 4. Can HTML be included without unrelated docs? — Only via ignore/exclude

`--code-only` is all-or-nothing for documents; there is no `--include` flag.
Dropping `--code-only` pulls in all 101 docs: 95 `.yaml` (form templates +
theme), 3 `.md` (README, agents, anvil-ui-build-standard), 2 `.html`, 1 `.txt`
(LICENSE). To scope, use `.graphifyignore` or the repeatable `--exclude
<pattern>` flag (functional but not listed in `extract --help` usage;
`cli.py` L2944).

## Recommended treatment of Anvil HTML templates

Naming note: "HTML templates" is a misnomer — the Anvil UI structure is
**95 `.yaml` form templates + 2 `.html` files**. Both are DOC/semantic-only.

- **If UI-structure coverage matters**: drop `--code-only`, provide an LLM
  backend, accept non-deterministic, token-costing semantic extraction of the
  templates.
- **If determinism/cost matter more**: stay `--code-only`; templates remain
  ghost/reference names (current state).

2. Persisted `{"gitignore": false}` stays; `.graphifyignore` still honored —
   verify noise actually disappears. (Re-honoring `.gitignore` requires
   manually resetting `.graphify_build.json` to `{"gitignore": true}` — a

   (Anvil loads templates by directory convention, no import/call edge).
5. No cross-language phantom edges: HTML/YAML extract as `file_type: document`,
   so no `calls` edges into Python (extraction-spec forbids them) — templates
   land as isolated document nodes, not fake call links.
6. Cost (Path B): ~101 docs through the LLM; no exact token estimate without a
   run.
7. Post-rebuild verification: `git status --porcelain` clean (only
   `graphify-out/` untracked); `graph.json` `built_at_commit == git rev-parse
   HEAD`; noise nodes (`source_file` contains `opencode`) = 0;
   `graphify path "get_vault_secret" "encrypt" --undirected` still returns the
