## 2. Duplicate / conflicting / stale instructions found

- **Duplicate file identity.** One physical file, two spellings. `$include`
  and the physical name use lowercase mb-3-cs; OpenCode convention and
  `/sync-gbrain` expect uppercase `AGENTS.md`. Harmless on this FS, but a
  latent break on any case-sensitive checkout (Linux CI/native):
  mb-3-cs and `/sync-gbrain`'s `[ -f AGENTS.md ]` would
  both miss.
- **GBrain described twice, at different specificity.** Global AGENTS.md has
  a detailed GBrain routing block (semantic search + symbol lookup); the
  project mb-3-cs has a single thin line. Not contradictory, but
  overlapping.
- **No Graphify guidance block exists.** Graphify is mentioned only in the
  "Access Model" line and via the transient plugin bash-reminder. This is the
  real gap the new block closes.
- **Untracked/gitignored status.** mb-3-cs, `opencode.json`,
  `.opencode/`, and `graphify-out/` are all gitignored — so all agent config
  is local-only and does not travel with the repo. Any "managed block" added
  here is local-only unless the file is deliberately un-ignored/renamed (a
  decision, not an assumption).

## 3. Proposed managed block (not yet written)

```markdown
<!-- BEGIN GRAPH MEMORY GUIDANCE -->
## Graph Memory Guidance

Two graph/memory tools are available; they answer different questions and
are never a substitute for the source itself.

- **Graphify** (local code-relationship graph, `graphify-out/graph.json`) is
  the authority for **current structural code relationships** — definitions,
  callers/callees, imports, containment — as the code exists now.
- **GBrain** (semantic memory, source `mb-3-cs-code`) is the authority for
  **decisions, rationale, history, research, and incidents** — why something
  was done, what was tried, what was decided.

Authority order:
1. **Current repository files, explicit user instructions, and tests** are
   authoritative over everything else.
2. **Graphify INFERRED or AMBIGUOUS edges must be verified against source**
   before being trusted; only EXTRACTED edges are reliable without re-check.
3. **Graph provenance must match the current Git commit.** If `graphify-out/`
   was generated from a commit other than HEAD, rebuild before relying on it.
4. **Important completed decisions may be written back to GBrain** so future
   sessions recover the rationale, not just the code.
5. **Neither graph replaces direct source inspection or testing.** Confirm any
   structural or historical claim in the source files before acting on it.
<!-- END GRAPH MEMORY GUIDANCE -->
```

All seven required statements are present:

1. Graphify handles current structural code relationships.
2. GBrain handles decisions, rationale, history, research, and incidents.
3. Current repository files, explicit user instructions, and tests are
   authoritative.
4. Graphify INFERRED or AMBIGUOUS edges require source verification.
5. Graph provenance must match the current Git commit.
6. Important completed decisions may be written back to GBrain.
7. Neither graph replaces direct source inspection or testing.

## 5. Would `/sync-gbrain` or Graphify overwrite it?

- **Graphify — No.** Verified: the plugin (`graphify.js`) only prepends a bash
  reminder string; the MCP server only reads `graph.json`. Neither writes to
  mb-3-cs/`AGENTS.md`. Zero overwrite risk.
- **`/sync-gbrain` — No direct overwrite, but a future append.** Its Step 4
  manages only its own delimiters
  (`<!-- gstack-gbrain-search-guidance:start/end -->`). It does not recognise
  `<!-- BEGIN GRAPH MEMORY GUIDANCE -->`, so it will **not** touch this
  block's contents. However, if `/sync-gbrain` is later run from the project
  root, it will `[ -f AGENTS.md ]` (true here) and **append its own
  `## GBrain Search Guidance` block** at the end of the same file → two
  GBrain-touching blocks. To keep them from conflicting, the proposed block
  scopes GBrain to the *memory* role (decisions/history) and deliberately
  defers *code-search* routing to the `/sync-gbrain` block, so they stay
  complementary rather than contradictory.
