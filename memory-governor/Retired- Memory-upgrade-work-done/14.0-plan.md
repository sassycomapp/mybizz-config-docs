## OpenCode compatibility

- The skills are **plain `SKILL.md` files with frontmatter** (`name`,
  `version`, `description`, `triggers`) — host-agnostic, **no Hermes or
  OpenClaw dependency** in the files themselves. Routing is
  frontmatter-`triggers:`-driven, per the scaffold contract.
- **Caveat:** they land at the workspace-root `skills/` directory, which
  OpenCode does **not** auto-discover (OpenCode looks in `.opencode/skills/`,
  `~/.config/opencode/skills/`, etc.). So scaffolded skills would act as
  reference files the agent reads, not as auto-registered OpenCode skills —
  unless later relocated into `.opencode/skills/` or wired via config.

## Whether execution should proceed

**Proceed with the dry-run only, then decide.** The dry-run is zero-write and
will confirm the exact 38-skill file list. The real scaffold is safe (additive,
workspace-scoped) but its value is currently limited by three things: (a) the
dispatcher `RESOLVER.md` is not copied, so skills won't auto-route; (b) OpenCode
won't auto-discover a root `skills/` dir; (c) the bundle is stale relative to
the CLI. Recommend: run the dry-run, review the JSON file list, and only commit
to the real scaffold if the skills are still wanted as reference files in the
test workspace.
